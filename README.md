# Star Empires

Star Empires — компактный прототип космической экономики на Java и libGDX. Станции
потребляют и производят ресурсы, рынок пересчитывает цены, глобальные события
меняют предложение и спрос, а автономные флоты ищут прибыльные торговые маршруты.
Ashley ECS отделяет состояние сущностей от систем обработки, Scene2D показывает
интерактивную звёздную карту, ленту новостей и состояние экономики.

## Требования и быстрый старт

- JDK 17; более новые JDK также поддерживают сборку, но для совпадения JAR байт в байт используйте ту же JDK 17, что и CI.
- Отдельно устанавливать Maven не нужно: репозиторий содержит Maven Wrapper.
- Для запуска desktop-приложения необходим графический сеанс с поддержкой OpenGL.

Самый простой запуск в Windows — двойной щелчок по `run.cmd` или команда из
PowerShell:

```powershell
.\run.cmd
```

Скрипт самостоятельно переходит в каталог проекта, проверяет наличие Java,
выполняет `clean package` через Maven Wrapper, запускает тесты и открывает
собранный `-all.jar`. При первом запуске Wrapper может загрузить Maven и
зависимости проекта из интернета.

Для одной сборки без открытия окна используйте `.\run.cmd --build-only`.

Полная проверка в Windows PowerShell:

```powershell
.\mvnw.cmd --batch-mode --no-transfer-progress clean verify
```

В Linux и macOS:

```bash
./mvnw --batch-mode --no-transfer-progress clean verify
```

Команда компилирует проект, запускает тесты, проверяет покрытие, строит русскую
Javadoc-документацию и создаёт оба JAR-файла. Самодостаточное desktop-приложение
находится в `target/star-empires-1.0-SNAPSHOT-all.jar`; обычный JAR без суффикса
`-all` не содержит библиотек и не предназначен для автономного запуска.

```powershell
java -jar target/star-empires-1.0-SNAPSHOT-all.jar
```

На macOS графический цикл LWJGL необходимо запускать в первом потоке:

```bash
java -XstartOnFirstThread -jar target/star-empires-1.0-SNAPSHOT-all.jar
```

## Управление картой

Мир увеличен до 2000×1400 условных единиц. Станции показаны цветными кругами,
астероиды — неровными каменными силуэтами с минеральным ядром, а пять классов
кораблей различаются одновременно формой и цветом. Линия в цвет корабля отмечает
его текущий торговый или добывающий маршрут. Выбранный объект получает жёлтую
подсветку.

- Нажмите левой кнопкой мыши на станцию, корабль или астероид, чтобы открыть
  справа его имя, координаты и доступные характеристики.
- Вращайте колесо над картой для приближения и отдаления вокруг курсора.
- Перетаскивайте свободную область левой кнопкой либо используйте среднюю или
  правую кнопку, чтобы перемещать увеличенный обзор.
- Колесо над правой карточкой или лентой новостей прокручивает их содержимое.
- При выборе станции на достаточно широком окне внизу карты появляется история
  цены первого торгуемого товара.

В демонстрационной сцене работают семь кораблей. Пять транспортов по-прежнему
закреплены за отдельными товарами и поддерживают все торговые маршруты: два
материаловоза перевозят руду и сталь, танкер — физический энергоноситель, а два
контейнеровоза — продовольствие и вооружение. Дополнительно в мире присутствуют
добывающий и боевой корабли.

Товары разделены на три категории груза:

- материалы: руда и сталь;
- газ/жидкость: энергия, которая в модели представляет перевозимый
  энергоноситель;
- готовые товары: продовольствие и вооружение.

Торговый ИИ выбирает маршрут только внутри допустимой категории грузового отсека.
Специализация по конкретному товару действует поверх этого ограничения. При первом
обновлении в удалённых точках астероидного пояса появляются четыре источника руды;
далее система раз в двадцать секунд пополняет их число до шести. Каждый астероид
содержит конечный запас от 36 до 84 единиц и исчезает после полного истощения.

Добывающий корабль не создаёт ресурс самостоятельно: он выбирает ближайший
астероид, летит к нему, добывает руду в пределах вместимости трюма, возвращается
на шахтёрскую базу и продаёт груз через тот же атомарный торговый контроллер.
Боевой корабль уже имеет корпус, щит, урон и дальность, но непосредственно сражения
пока не моделируются.

Экономика образует полноценную производственную сеть:

```text
астероидная руда ──────> шахтёрская база ──────> кузница
энергия ───────────────> продовольствие
руда + энергия ────────> сталь
сталь + энергия ───────> вооружение
```

Добывающий корабль доставляет астероидную руду на базу, энергоузел создаёт второй
первичный ресурс, агрокупол превращает энергию в продовольствие, кузница — руду и
энергию в сталь, арсенал — сталь и энергию в вооружение. Колония поддерживает
конечный спрос. Все входы и выходы явно торгуются на рынках.

## Архитектура

| Пакет | Ответственность |
| --- | --- |
| `components` | Данные Ashley-сущностей: астероид, корабль, инвентарь, рынок, производство, добыча, бой, репутация и позиция |
| `systems` | Появление астероидов, потребление, производство, добывающие и торговые маршруты, цены и история |
| `controllers` | Атомарное исполнение покупок и продаж |
| `events` | Глобальные экономические события и новости |
| `model` | Категории товаров, классы кораблей, рецепты и конфигурация астероидного пояса |
| `util` | Пространственный индекс ближайших сущностей |
| `ui` | Карта и hit-test объектов, карточка выбора, адаптивные Scene2D-панели и график цены |
| `desktop` | Конфигурация и запуск LWJGL3 |

Главные правила экономической модели:

- скорость потребления и производства зависит от прошедших секунд, а не от числа
  кадров;
- большой конечный `deltaTime` в производстве обрабатывается пакетно, а генератор
  событий ограничивает объём работы одного обновления;
- торговать можно только явно настроенными на рынке товарами;
- добыча сохраняет ресурс: каждая единица одновременно вычитается из конечного
  запаса астероида и добавляется в трюм;
- событие влияет только на указанный товар и после завершения перестаёт действовать без накопления ошибки;
- покупка или продажа либо применяет все изменения запасов и балансов, либо не меняет ничего;
- конфигурационные и торговые API отклоняют `NaN`, бесконечности, переполнение
  запасов и незаметные для `float` изменения баланса;
- торговый ИИ перепроверяет исполнимость маршрута и восстанавливается после
  исчезновения или отказа станции;
- интерфейс ограничивает число новостей, обновляет тяжёлую сводку не чаще четырёх
  раз в секунду и безопасно переживает изменение размера окна.

Порядок систем задаётся в `SpaceSimGame`: рынок → потребление → производство →
появление астероидов → добыча и разгрузка → торговый ИИ → запись цен. Изменение
этого порядка может поменять экономический результат одного кадра.

## Проверки и отчёты

JUnit-тесты покрывают контроллер торговли, репутационные цены, рыночные события,
потребление, производство, конечную добычу, периодическое появление астероидов,
типы кораблей и товаров, торговый ИИ, запись цен, пространственный индекс и чистую
логику UI, включая zoom, pan, проекцию карты и выбор объектов. Отдельные проверки
демонстрационного мира доказывают наличие спроса и предложения для каждого
товара, исполнимость всех рецептов и выбор пяти специализированных маршрутов.
В фазе `verify`
JaCoCo требует не менее 70% покрытия строк и 60% покрытия ветвей. Тонкая граница
с реальным OpenGL/LWJGL (`SpaceSimGame`, desktop-запускатель и непосредственно
`WorldMapRenderer`) исключена из числового порога и проверяется ручным
desktop smoke-тестом; модель, преобразование координат и hit-test остаются в
автоматическом отчёте.

После успешной проверки доступны:

- `target/site/jacoco/index.html` — интерактивный отчёт о покрытии;
- `target/site/apidocs/index.html` — Javadoc API на русском;
- `target/surefire-reports/` — результаты тестов;
- `target/star-empires-1.0-SNAPSHOT-all.jar` — запускаемое приложение.

GitHub Actions выполняет ту же команду `clean verify` на JDK 17 и сохраняет
приложение, Javadoc, покрытие и тестовые отчёты как артефакты workflow.

Тесты UI не создают настоящее OpenGL-окно. Перед выпуском рекомендуется вручную:

1. Запустить `-all.jar` в окне 1280×720.
2. Выбрать станцию, каждый класс корабля и астероид, проверить подсветку, карточку,
   уменьшение конечного запаса и обновление координат добытчика.
3. Уменьшить окно до 800×600 и убедиться, что правая карточка, новости и сводка
   не закрывают кликабельную область карты.
4. Проверить zoom колесом над картой, pan всеми поддерживаемыми кнопками и
   независимую прокрутку UI-панелей.
5. Изменить размер окна несколько раз, затем закрыть приложение без ошибок
   освобождения ресурсов.

## Совместимость API

В ходе стабилизации модели несколько ранее открытых деталей реализации получили
защищённый API:

- массивы входов и выходов `Recipe` доступны через методы чтения;
- репутация изменяется методами `ReputationComponent`, а не прямой записью массива;
- ссылка `InventoryComponent.stock` неизменяема, хотя элементы массива по-прежнему изменяемы;
- прежний пустой класс `ItemType` заменён перечислением конкретных товаров с
  устойчивыми числовыми идентификаторами, категорией груза и базовой ценой;
- `PriceGraphRenderer.render(...)` теперь принимает `Matrix4` камеры, чтобы рисовать в координатах Scene2D.

Клиентский код, который создавал `new ItemType()`, напрямую переназначал эти поля
или вызывал старую сигнатуру отрисовщика, необходимо адаптировать.
