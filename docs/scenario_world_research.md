# Минимальный мир для сценарных тестов — исследование

2026-10-17. Этап 2.1 из [development_process_plan.md](development_process_plan.md).
Источники: Codex researcher (read-only), проверка по коду и замеры одноразовыми probe-программами.

## Как устроен мир сейчас

- Мир строится только генератором:
  `Stage228CampaignAuthority.create(seed)` → `GeneratedCampaignCoordinator.create` →
  `GeneratedCampaignSession.create` → `Stage20PlayableGeneratedWorldFactory.create` →
  `Stage20ResolvedGeneratedWorldProductionProbe.runCurrent(seed)`. Профиль генератора
  через фабрику не передаётся.
- Единственный шов для готового мира — `Stage228CampaignAuthority.restore(checkpoint)`.
  Каждая команда игрока внутри тоже делает `captureState → restore`, поэтому
  checkpoint должен быть полным и валидным уже до первого save/load.
- Команды сценария: `previewPilotAction/submitPilotAction`, `setPilotThrust`,
  `advanceFrame(fixedStepSeconds)`. Вызов одного `WorldSimulation.advanceFrame`
  пропускает личное движение, добычу и обслуживание (`Stage228CampaignAuthority:2326`).
- Существующие быстрые тесты (`GeneratedCampaignNpcSupplyOffersTest:249`) телепортируют
  корабль через `completeFleetTransfer/updatePhysicalState` — для приёмки сценарием не годится.

Ограничения ручного мира (проверены по коду):
- минимум одна связь между системами и hubs (`Stage20FreightRuntimeMaterializer:737`);
- хотя бы одна промышленная специализация (`Stage20IndustrialEntityMaterializer:556`);
- продаваемый шахтёр должен соответствовать `MINING_RESERVE_VERSION`, `faction.beta`,
  IDLE и иметь старший из ≥2 RESERVE slots (`GeneratedCampaignPlayerCheckpointValidator:22`);
- source snapshots, fingerprints, clocks и ownership проверяются на нескольких уровнях.

## Замеры

| Что | Значение |
|---|---|
| Создание кампании seed 1 | 4,9 с |
| Скорость симуляции после старта пилота | ~7000 тиков/с; тик = 0,1 с игрового времени (≈700× реального) |
| Seed 1, старт пилота | система 16, у `hub.16` (рынок, 301 м); 6 IDLE-грузовиков в 0,8–4,2 км |
| Seed 1, ближайший FREE_BODY источник | 15,0 млн м от старта |
| Лучшая пара станция–источник во всей галактике seed 1 | 3,3 млн м (`industry.21`) |
| Seeds 4, 6, 8 | генерация отклонена (нет принятой specialization) |

Перелёт на 15 млн м: при 1500 м/с — ~100 тыс. тиков (~15 с), при 150 м/с — ~1 млн тиков
(~2,5 мин). Значит, медленными QA-путешествия делает не размер мира, а межсистемные маршруты,
низкая крейсерская скорость из-за топлива и многомиллионные сегменты.

## Варианты

| Вариант | Стоимость | Скорость теста | Риск |
|---|---|---|---|
| **A. Сгенерированный seed 1, цикл в одной системе** | малая: кешированный checkpoint как `GeneratedCampaignFixture`, но с `CIVILIAN_MINING_RESERVE` и стартом пилота | ~5 с создание (кеш) + 30–60 с полёта, если топливо позволяет ~1500 м/с | зависит от генератора; дистанции не управляются |
| **B. Ручной checkpoint из 2 систем** (рекомендация Codex) | большая: согласовать канонические строки, Stage21 A–I, sidecars | секунды | сопровождение при смене схемы; легко незаметно обойти инвариант |
| C. Генератор с маленьким профилем | средняя: протянуть профиль через фабрику | неизвестно | малое число систем не даёт коротких локальных дистанций |
| D. `PlayableTestWorldFactory` | — | — | другая модель мира (DemoGalaxy), не Stage20/228 |

## Рекомендация

Начать с **A**, а **B** делать только если A окажется медленнее 60 с или нестабильным.

A уже даёт главное: обычный путь (команды игрока + такты + save/load) в JUnit, детерминированно,
в обычном `verify`, а не многочасовой прогон. Если цикл упрётся в топливо, это будет
находка по балансу за минуту теста, а не за часы.

Первый сценарий A (seed 1, система 16):
1. Кешированный checkpoint: `create(1L)` с `CIVILIAN_MINING_RESERVE`, затем
   `previewIndependentPilotStart/submitIndependentPilotStart`.
2. `DOCK hub.16` → покупка карты ресурса у диспетчера (если есть) или явная запись,
   что координата источника взята из runtime → `PURCHASE` шахтёра → `UNDOCK`.
3. Полёт тягой к источнику, `START_MINING` (килограммы — на тик), save/restore посреди добычи,
   `STOP_MINING`, возврат, `DOCK`, `SELL`, `BUY_CONSUMABLE` (топливо).
4. Проверки: сохранение денег (кошелёк/рынок/казна) и массы (источник/трюм/склад/бак),
   точный round-trip, отсутствие повторной оплаты/добычи после restore.
5. `@Tag("scenario")`, бюджет тиков ограничен; замерить реальное время.

Открытый вопрос: откуда игрок знает координату источника. Ordinary-путь — оплаченная карта
у диспетчера; если её нет у `hub.16`, это отдельное решение (авторская стартовая карта
или находка по дизайну).
